# M21 Phase 3 Strategy — Post-deploy Verification and Rollout Sign-off

Status: Draft for review — execution not started.
Parent milestone: [`21_OB_DEPLOYMENT.md`](../milestones/21_OB_DEPLOYMENT.md)
Prerequisite: [M21.2 — Deploy and cutover](21.2_DEPLOY_AND_CUTOVER.md) complete.

Goal: verify public journeys and operations, resolve rollout findings, and obtain acceptance. [Shared references](../milestones/21_OB_DEPLOYMENT.md#execution-references) govern workflow and operations.

Use operator-controlled accounts, clients, and inboxes for smoke tests. [M20.5](x20.5_LIVE_MAINNET_VALIDATION_BACKOUT.md) supplies the existing payment, mail, and recovery evidence.

Safe parallel work: after §1, public-site checks (§5) and runbook review (§6) can run alongside app/mail verification (§§2–3).

## 1. [ ] Verify deployment health

1. [ ] Verify release tags, applied migrations, and production/mainnet/apex configuration against the cutover record across app, queue, scheduler, and site.
2. [ ] Run the [service and watcher health checks](../ops/RUNNING_THE_SERVER.md#reading-health-honestly).
3. [ ] Inspect queue failures and application/mail/watcher logs for cutover errors.
4. [ ] Verify the first post-cutover backup and off-box pull against the [backup requirements](../ops/RUNNING_THE_SERVER.md#backups).

## 2. [ ] Verify issuer, payer, and legal journeys

1. [ ] Verify Phase 2's new account completes applicable account verification and wallet onboarding without alpha approval.
2. [ ] Verify existing-account access and email/TOTP 2FA on the apex.
3. [ ] Verify the cutover smoke invoice's address belongs to the expected wallet.
   1. [ ] Verify its signed-out share view: amounts, QR, status, and noindex.
4. [ ] Verify a second issuer cannot access the first issuer's invoices or clients or receive private details in denied responses.
5. [ ] Verify pre-cutover links, including signed links, follow the agreed old-host handling; fresh links use the apex.
6. [ ] Verify legal placements against [M19.5](x19.5_LEGAL_LAYER.md).
7. [ ] [User] Review live landing/legal pages and invoice screen/print in both themes and at mobile width.

## 3. [ ] Verify payment integrity and production mail

1. [ ] Reconcile existing payment records with the chain using [M20.5 §6](x20.5_LIVE_MAINNET_VALIDATION_BACKOUT.md#6-x-verification).
   1. [ ] Verify USD snapshots and settlement times against the [confirmation/tolerance rules](../specs/PARTIAL_PAYMENTS+CONFIRMATIONS.md).
   2. [ ] Verify existing invoice/donation records and allocation state remain separate; assess any new discrepancy under [M21.1 §3](21.1_PRE_DEPLOY_VERIFICATION.md#3---check-wallets-against-the-alpha-baseline).
2. [ ] Record whether the deployed delta or failed checks require live-payment revalidation beyond [M20.5 §§1–2](x20.5_LIVE_MAINNET_VALIDATION_BACKOUT.md#1-x-real-invoice-end-to-end).
   1. [ ] For required revalidation, prepare the affected operator-owned scenario after wallet validation passes.
   2. [ ] [User] Send the required payment from the source wallet.
   3. [ ] Verify the scenario against M20.5's detection, settlement, attribution, and notice checks; record the verdict.
   4. [ ] [User] Confirm any new payments appear as expected in the source wallets.
3. [ ] Inspect M21.2 §5's invoice/receipt delivery rows against provider events for truthful status and no duplicate sends or stranded deliveries.
4. [ ] Verify those messages' apex links work signed out where appropriate.
5. [ ] [User] Inspect those received messages for sender, rendering, un-aliased recipients, and aligned SPF/DKIM/DMARC pass.

## 4. [ ] Discharge the conditional mail-stress carry

1. [ ] Recheck M21.1 §5's [#81](https://github.com/n8bar/CryptoZing/issues/81) upgrade/switch trigger against the deployed mailer and quota.
   1. [ ] For a triggered rerun, execute the applicable [M19.1 §6 scenarios](x19.1_NOTIFICATION_COVERAGE_AUDIT.md#6-stress-readiness-check-best-effort) with contained recipients and isolated failure injection.
2. [ ] Record scenario verdicts and remaining limits, or retain the untriggered carry with its future owner.

## 5. [ ] Verify public discovery and analytics

1. [ ] Compare the landing page, published article URLs, and assets with the M21.1 baseline for missing paths or changed redirects.
2. [ ] Verify HTTPS/non-`www` redirects, canonicals, social metadata, structured data, robots, and sitemap behavior.
3. [ ] Verify apex publication is indexable and alpha/staging/public invoice exclusions remain intact.
4. [ ] [Guided User] Verify Search Console/Bing ownership and root/sitemap fetches; distinguish indexing delay from fetch/canonical regressions.
5. [ ] Verify marketing analytics reaches M21.1 §6's selected endpoint and matches the live Privacy Policy.
6. [ ] Verify app, invoice, and staging pages send no analytics events and marketing events are not duplicated.

## 6. [ ] Verify operations and resolve rollout findings

1. [ ] Verify the [operating runbook](../ops/RUNNING_THE_SERVER.md) and [self-host guide](../ops/get-live/README.md) match the release; correct any drift.
2. [ ] Confirm recovery access, rollback tags, and halt instructions remain usable on the apex, using M21.1's restore and M20's halt evidence.
3. [ ] Resolve rollout findings and repeat affected checks; submit remaining deferrals for §7 acceptance.
4. [ ] Check for real customer data and update AGENTS.md's data-hygiene note accordingly.

## 7. [ ] Obtain sign-off and close the milestone

1. [ ] Present deployed tags and §§1–6 verdicts, including analytics, #81, and proposed deferrals.
2. [ ] [User] Confirm the public deployment is fit for open beta after reviewing the evidence and any accepted deferrals.
3. [ ] Complete the [milestone's content-promises check](../milestones/21_OB_DEPLOYMENT.md#exit-criteria).
4. [ ] Close M21 and hand discovery observations and accepted follow-ups to [M22](../milestones/22_SEO_MARKETING.md).

## Exit Criteria

- [ ] §§1–6 pass with no unresolved launch blocker and accepted dispositions for remaining findings.
- [ ] The operator accepts open beta; content promises pass and M21's closeout/M22 handoff is complete.
