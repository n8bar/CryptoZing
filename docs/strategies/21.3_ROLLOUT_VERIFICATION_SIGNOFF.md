# M21 Phase 3 — Verify the Public Result and Sign Off

Status: Approved by n8 - 9/5/2026 21:28.
Parent: [M21](../milestones/21_OB_DEPLOYMENT.md)
Prerequisite: [M21.2](21.2_DEPLOY_AND_CUTOVER.md) complete.

Goal: verify the changed public entry points and accept the in-place transition. M20's wallet/payment/provider proofs remain the [accepted baseline](../milestones/21_OB_DEPLOYMENT.md#accepted-baseline).

Parallel work: public URL checks (§2) and service observation (§3) can run alongside the account smoke (§1).

## 1. [ ] Verify public access and links

1. [ ] Register an operator-controlled account and confirm it can sign in and reach wallet setup without manual alpha approval.
2. [ ] Using the existing verified operator account, create an invoice and open its enabled share link signed out.
   1. [ ] Verify the apex URL, displayed invoice/QR, and noindex; do not onboard another copy of the operator wallet or send another payment.
3. [ ] [User] Check Phase 2's received invoice email and open its apex link. Reuse that delivery; no second send is needed.
4. [ ] Confirm old alpha URLs behave according to the approved retirement disposition.

## 2. [ ] Verify public-site continuity

1. [ ] Compare the published URL inventory with Phase 1's baseline on the new serving path.
   1. [ ] Resolve missing articles/assets, changed redirects, or broken sitemap/verification files.
   2. [ ] Verify public canonicals/indexing and retained staging/invoice noindex.
2. [ ] Verify the landing page has its intended metadata, guides navigation, and working policy links; policies have the publication date and agreed analytics wording.
3. [ ] Verify the selected analytics endpoint receives landing/article views without duplicate collection or events from excluded surfaces.

## 3. [ ] Confirm operation and accept the release

1. [ ] Check [service health and watcher progress](../ops/RUNNING_THE_SERVER.md#reading-health-honestly) after the final restarts; inspect logs/queue failures for cutover errors.
2. [ ] Resolve cutover findings and repeat only their affected checks; present any proposed deferrals for acceptance.
3. [ ] Correct deployment/runbook references changed by alpha retirement; update AGENTS.md's data-hygiene note if real customer data now exists.
4. [ ] [User] Accept the public deployment after reviewing the cutover and verification verdicts.
5. [ ] Complete the [milestone's content-promises check](../milestones/21_OB_DEPLOYMENT.md#exit-criteria), close M21, and hand discovery observations and accepted follow-ups to [M22](../milestones/22_SEO_MARKETING.md).

## Exit Criteria

- [ ] Public access, hostname retirement, mail links, and content/publication checks pass.
- [ ] Services are healthy and the watcher advances, with no unresolved cutover blocker; the operator accepts the result and M21's closeout is complete.
