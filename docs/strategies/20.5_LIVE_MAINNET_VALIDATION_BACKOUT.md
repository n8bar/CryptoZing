# MS20 Phase 5 Strategy — Live Mainnet Validation & Backout

Status: In Progress.
Parent milestone doc: [`docs/milestones/20_MAINNET_CUTOVER_ALPHA_GATE.md`](../milestones/20_MAINNET_CUTOVER_ALPHA_GATE.md)
Supporting ops doc: [`docs/ops/OB_ROLLOUT_CHECKLIST.md`](../ops/OB_ROLLOUT_CHECKLIST.md)

**Goal:** Prove the payment pipeline with real self-sent mainnet money — an invoice and a donation, each end to end — exercise the correction tooling against live data, and leave behind a cutover runbook and a halt procedure that MS21 executes.

Real funds move in this phase. Self-sending means the coins come back and the fee is the only real cost, but none of it is reversible by anything in §5.

## 5. [x] Runbook and halt procedure

1. [x] Write the cutover runbook from what this phase actually did, not from what we planned.
   1. [x] Environment flips, in the order they have to happen. Ordered so the silent failures cannot happen: TLS before anything points at the hostname, webroot renewal before nginx takes port 80, and every service recreated rather than the app alone.
   2. [x] Wallet validation before funds move. `wallet:check-config` as the gate, index-by-index derivation against the source wallets diffed fresh rather than against an earlier transcript, and a mismatch stops the cutover.
   3. [x] Mail sanity checks. Carries the webhook re-registration against the new hostname, which is the step a host change orphans silently.
   4. [x] Post-deploy checks and who signs them off. Owner column per check, Agent or User.
2. [x] Write the halt procedure for a cutover going wrong.
   1. [x] Stop the watcher and queue worker so nothing auto-acts on bad state. `stop queue scheduler` — the watcher is a per-minute scheduled run inside the scheduler, not its own service.
   2. [x] Set `MAIL_OUTBOUND_ENABLED=false` so no mail goes out on a wrong assumption.
   3. [x] Roll back to the previous image tag. Prior shas stay cached on the box, so the rollback needs no registry pull.
   4. [x] Restore the database from the most recent verified backup. Dumps are `age`-encrypted with the identity off-box, so the box cannot restore itself — the runbook says so where a halt would otherwise discover it.
   5. [x] State plainly what a halt cannot undo: coins already sent, and mail already delivered. Also webhook events third parties already acted on, anything a customer already loaded, and everything recorded between the dump and the halt.
3. [x] Prove the halt procedure by running it, then bring the box back up. Run end to end against prod: workers stopped, mail disabled, rolled back to `654b160`, restored from a fresh encrypted dump validated in a scratch database, then recovered to `868dce2` with all services healthy and the watcher ticking. A marker row planted before the halt was gone afterward, so the restore demonstrably replaced data. Two defects in the written procedure surfaced and are now fixed in it: `up -d` restarts the workers step 1 stopped, and a restored dump reinstates the watcher's `withoutOverlapping()` mutex — root fix tracked in [#174](https://github.com/n8bar/CryptoZing/issues/174).
4. [x] Fold both into [`docs/ops/OB_ROLLOUT_CHECKLIST.md`](../ops/OB_ROLLOUT_CHECKLIST.md), which is what MS21 executes. Rebuilt around the two procedures; the prior checklist's still-live items were carried over and its historical notes dropped.
5. [x] Resolve every Issue the rehearsal raised, so the procedures MS21 executes carry no known open defect. [#174](https://github.com/n8bar/CryptoZing/issues/174) closed — `cache`, `cache_locks`, and `sessions` now dump schema-only on the box and in the published recipe, verified by restoring a dump cut with a lock planted and watching the watcher restamp itself unaided. The repo has no open Issues.
