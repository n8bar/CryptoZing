# MS20 Phase 5 Strategy — Live Mainnet Validation & Backout

Status: In Progress.
Parent milestone doc: [`docs/milestones/20_MAINNET_CUTOVER_ALPHA_GATE.md`](../milestones/20_MAINNET_CUTOVER_ALPHA_GATE.md)
Supporting ops doc: [`docs/ops/OB_ROLLOUT_CHECKLIST.md`](../ops/OB_ROLLOUT_CHECKLIST.md)

**Goal:** Prove the payment pipeline with real self-sent mainnet money — an invoice and a donation, each end to end — exercise the correction tooling against live data, and leave behind a cutover runbook and a halt procedure that MS21 executes.

Real funds move in this phase. Self-sending means the coins come back and the fee is the only real cost, but none of it is reversible by anything in §5.

## 4. [ ] Correction tooling against live data

This is the first chance to run the MS14 tooling against real on-chain conditions rather than fixtures.

1. [ ] Construct a wrong-attribution scenario on the live data — record-level, against the §1 payment and a second invoice.
2. [ ] Ignore the misattributed payment and confirm the invoice total corrects.
3. [ ] Restore it and confirm the total returns.
4. [ ] Reattribute it to the correct invoice and confirm both invoices land right.
5. [ ] Confirm the audit trail shows who did what, and when.
6. [ ] File any gap found as a GitHub Issue.

## 5. [ ] Runbook and halt procedure

1. [ ] Write the cutover runbook from what this phase actually did, not from what we planned.
   1. [ ] Environment flips, in the order they have to happen.
   2. [ ] Wallet validation before funds move.
   3. [ ] Mail sanity checks.
   4. [ ] Post-deploy checks and who signs them off.
2. [ ] Write the halt procedure for a cutover going wrong.
   1. [ ] Stop the watcher and queue worker so nothing auto-acts on bad state.
   2. [ ] Set `MAIL_OUTBOUND_ENABLED=false` so no mail goes out on a wrong assumption.
   3. [ ] Roll back to the previous image tag.
   4. [ ] Restore the database from the most recent verified backup.
   5. [ ] State plainly what a halt cannot undo: coins already sent, and mail already delivered.
3. [ ] Prove the halt procedure by running it, then bring the box back up.
4. [ ] Fold both into [`docs/ops/OB_ROLLOUT_CHECKLIST.md`](../ops/OB_ROLLOUT_CHECKLIST.md), which is what MS21 executes.

## Exit Criteria

- [x] Real self-sent mainnet invoice validated end to end: derived → paid → detected → confirmed → marked paid → receipt mail.
- [x] Real self-sent mainnet donation validated end to end: derived → paid → recorded on the donation row (never as an invoice) → operator notification mail.
- [ ] MS14 correction tooling exercised against a wrong-attribution scenario on live mainnet data; every Issue it raised is closed or deferred with a stated reason.
- [ ] Mail sanity on mainnet: correct `APP_PUBLIC_URL` links and headers; DKIM, SPF, and DMARC confirmed; delivery status flowing back through the webhook.
- [ ] Cutover runbook complete and proven by execution.
- [ ] Halt procedure proven by execution, with its limits stated.
- [ ] restrict outbound mail to the prod env + if possible allow the dev env too.
