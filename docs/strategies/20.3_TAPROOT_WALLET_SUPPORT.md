# MS20 Phase 3 Strategy — Taproot Wallet Support

Status: In Progress — §1–§2 complete (PR [#143](https://github.com/n8bar/CryptoZing/pull/143)); §3 verification underway.
Parent milestone doc: [`docs/milestones/20_MAINNET_CUTOVER_ALPHA_GATE.md`](../milestones/20_MAINNET_CUTOVER_ALPHA_GATE.md)
Supporting spec: [`docs/specs/WALLET_XPUB_UX_SPEC.md`](../specs/WALLET_XPUB_UX_SPEC.md)

**Goal:** The watch-only wallet layer accepts Taproot (BIP86) account keys and derives bech32m (`bc1p`/`tb1p`) receive addresses for invoices and donations, so the Phase 4 operator wallets — and merchants at cutover — can be Taproot. Watch-only invariant unchanged: public keys in, addresses out, nothing that can sign.

## Decisions to confirm before flesh-out

1. Protocol coverage: Taproot (BIP86) only, or also other onboarding gaps surfaced by the same review (wrapped SegWit/BIP49, descriptor input, multisig)? _Answer:_ Taproot + descriptor input (`wpkh(...)`/`tr(...)`). Named exclusions, recorded in the spec: wrapped SegWit/BIP49, Silent Payments (BIP352 — detection needs a scan key, doesn't fit address-polling watch-only), Lightning (separate layer; sequenced after Ethereum support, which itself is deliberately not backlogged). Multisig stays in [`docs/BACKLOG.md`](../BACKLOG.md) §3.
