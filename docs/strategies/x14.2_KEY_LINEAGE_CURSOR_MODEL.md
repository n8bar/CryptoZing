# MS14 Phase 2 Strategy - Key Lineage + Cursor Model

Status: Completed.
Parent milestone doc: [`docs/milestones/x14_PAYMENT_ATTRIBUTION_HARDENING.md`](../milestones/x14_PAYMENT_ATTRIBUTION_HARDENING.md)

Create a durable per-key cursor ledger and remove legacy per-wallet cursor state.

## 2.1 Add the lineage schema %<8718>
1. [x] Create `wallet_key_cursors` with `user_id`, `network`, `key_fingerprint`, `next_derivation_index`, `first_seen_at`, and `last_seen_at`. %<8719>
2. [x] Add a unique index on (`user_id`, `network`, `key_fingerprint`). %<8720>
3. [x] Add `wallet_key_fingerprint` and `wallet_network` to `invoices` so every newly assigned invoice stores its key lineage snapshot. %<8721>
4. [x] Drop `wallet_settings.next_derivation_index` so `wallet_key_cursors` becomes the only derivation-state source. %<8722>
5. [x] Drop `user_wallet_accounts.next_derivation_index` so additional wallet rows remain saved public-key metadata only. %<8723>
6. [x] Implement key fingerprinting consistently: %<8724>
   1. [x] normalize xpub input the same way validation does (trim/remove whitespace) %<8725>
   2. [x] compute `key_fingerprint = sha256("<network>|<normalized_xpub>")` %<8726>
   3. [x] store the hex digest without storing plaintext xpub outside the existing encrypted columns %<8727>

## 2.2 Persist active-key lineage on wallet save and invoice creation %<8728>
1. [x] Compute the active key fingerprint whenever the primary wallet is saved. %<8729>
2. [x] Upsert the active key's cursor row when saving wallet settings. %<8730>
3. [x] Initialize a brand-new key cursor at `0`. %<8731>
4. [x] Resume from the existing cursor row when a previously used key is saved again. %<8732>
5. [x] Clamp the active cursor to the safety floor `highest_assigned_for_same_key + 1` before issuing new assignments. %<8733>
6. [x] Derive each new invoice address from the active key plus the active cursor row. %<8734>
7. [x] Persist `derivation_index`, `wallet_key_fingerprint`, and `wallet_network` when creating the invoice. %<8735>
8. [x] Increment only `wallet_key_cursors.next_derivation_index` after a successful invoice create. %<8736>

## 2.3 Switch runtime and command paths to invoice-bound lineage %<8737>
1. [x] Update payment watch/sync to resolve network from `invoices.wallet_network` first. %<8738>
2. [x] Update payment watch/sync to use `invoices.wallet_key_fingerprint` as the invoice-bound lineage context instead of whichever wallet is currently saved. %<8739>
3. [x] Log and skip any invoice that still lacks key lineage instead of guessing. %<8740>
4. [x] Update `wallet:assign-invoice-addresses` to allocate from `wallet_key_cursors` and persist invoice lineage columns with each assignment. %<8741>
5. [x] Update `reassign-invoice-addresses` so any rewritten address/index also rewrites `wallet_key_fingerprint` and `wallet_network` from the selected key lineage instead of relying on removed wallet-row counters. %<8742>

## 2.4 Remove legacy cursor assumptions from tests, fixtures, and notes %<8743>
1. [x] Update factories and seeders to stop setting removed `next_derivation_index` columns on wallet rows. %<8744>
2. [x] Update feature and unit tests to assert cursor-ledger behavior instead of wallet-row counters. %<8745>
3. [x] Remove or update any docs and ops notes that still describe wallet rows as owning derivation state. %<8746>
