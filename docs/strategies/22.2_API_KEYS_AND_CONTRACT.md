# M22 Phase 2 — API Keys and Contract

Status: Draft.
Parent: [M22](../milestones/22_LINE_ITEMS_DEVELOPER_API.md), Phase 2.
Spec: [DEVELOPER_API.md](../specs/DEVELOPER_API.md).

Goal: an issuer can make and revoke API keys, requests with a key are authenticated and rate limited, and the request and response contract is written down before the endpoints exist.

Parallel work: §1 and §2 can run side by side. §3 waits for both.

## 1. [ ] Keys

1. [ ] Add the API key table and model: issuer, name, key hash, last used, revoked at.
2. [ ] Issuer settings page: make a key, see it once in full, see the list with last used, revoke one.
3. [ ] Authenticate API requests by bearer key and resolve the issuer; a revoked or unknown key is refused.
4. [ ] Rate limit per key; a limited request says when to retry.

## 2. [ ] Contract

1. [ ] Write `docs/API.md`: create, read, edit draft, delete, and send; one request and one response example each.
2. [ ] Define the invoice representation: lines, total, public link, payment details, mail state, payment state.
3. [ ] Define the idempotency rule for create: the same request key returns the first invoice.
4. [ ] Define the error format: one stable code plus the field or rule that failed, with the list of codes.

## 3. [ ] Verify

1. [ ] [Agent] Targeted tests: key creation, one-time reveal, revoke, refused requests, rate limit, and the error format.
2. [ ] [Agent] Full Sail suite.
3. [ ] [Subagent] Browser check of the key settings page on desktop and mobile widths.
4. [ ] [User] Review the key settings page on dev and the contract in `docs/API.md`.
5. [ ] [Agent] Record the dev verdict in the milestone doc.

## Exit Criteria

- [ ] A key can be made, used, and revoked on dev, and a revoked key is refused.
- [ ] `docs/API.md` covers every endpoint and state in [DEVELOPER_API.md](../specs/DEVELOPER_API.md).
- [ ] The full suite is green, the dev verdict is recorded, and Phase 2 is checked off.
